# 智慧运维页UI开发文档

## 1. 页面定位

智慧运维页是建筑能耗管理与运维系统中的日常工作台，面向运维工程师、值班长和能源管理人员。

页面目标不是展示方案汇报，而是支持日常值守、告警处置、工单推进和智能体辅助分析。页面首屏需要让用户快速判断：

- 当前站点是否健康
- 活跃告警有多少，优先级如何分布
- 哪些工单需要推进
- 当前最该处理的设备是什么
- 智能体能否直接解释异常并给出处置步骤

页面入口：

- 页面主体：`apps/editor/features/operations/components/smart-operations-workspace.tsx`
- 数据快照：`apps/editor/features/operations/lib/operations-dashboard.ts`
- 概览面板：`apps/editor/features/operations/components/operations-overview-panel.tsx`
- 全局样式：`apps/editor/app/globals.css`
- Next 配置：`apps/editor/next.config.ts`

访问地址：

```text
http://localhost:3002/?workspace=smart-operations
```

## 2. 设计目标

智慧运维页按“真实运维平台”设计，不按 PPT 展示页设计。

核心原则：

| 原则 | 说明 |
|---|---|
| 运维语境 | 使用工程师日常表达，避免“建设建议”“协同大界面”等汇报措辞 |
| 数据自洽 | KPI、告警中心、工单列表、状态栏的数字口径必须一致 |
| 信息分层 | 顶部看状态，中部看告警和工单，右侧看运维焦点和智能体 |
| 操作导向 | 每条异常都要能落到设备、时间、责任人、工单和下一步动作 |
| 视觉克制 | 保留科技感，但降低强发光、炫技线条和无意义装饰 |

## 3. UI 架构

页面由四层组成：

| 层级 | 说明 |
|---|---|
| 宿主框架 | 左侧导航、顶部系统状态、时间、天气、消息和设置 |
| 运维页头部 | 页面标题、面包屑、设备筛选、健康运行状态、实时钟、天气 |
| 运维工作区 | KPI、优先事项、告警中心、巡检与工单、待优化项、当前运维焦点 |
| 智能体交互层 | 推荐问题、问答气泡、5 秒思考态、流式输出、相关追问 |

页面主结构：

```text
SmartOperationsWorkspace
├─ 页面头部
├─ 5 个 KPI 卡片
├─ 左侧工作流
│  ├─ 优先事项
│  ├─ 告警中心
│  ├─ 巡检与工单
│  └─ 待优化项
├─ 右侧辅助区
│  ├─ 当前运维焦点
│  └─ 智能体问答
└─ 底部状态栏
```

## 4. 数据口径

页面使用固定运维快照，保证不同模块之间数据一致。

### 4.1 顶部 KPI

| 指标 | 值 | 副文案 | 对应模块 |
|---|---:|---|---|
| 站点健康度 | 97 分 | 较昨日 +2 | 健康评分 Tooltip |
| 活跃告警 | 5 条 | 高优 1 · 中优 3 · 低优 1 | 告警中心 5 条 |
| 待处理工单 | 2 条 | 超期 0 · 即将到期 1 | 工单列表 2 条 |
| 巡检覆盖率 | 99% | 本月累计 412 次 | 巡检口径 Tooltip |
| 智能体状态 | 已接入 | 平均响应 1.2s · v2.4.1 | 智能体问答 |

### 4.2 告警中心

告警中心固定展示 5 条活跃告警：

| 优先级 | 数量 | 说明 |
|---|---:|---|
| 高优 | 1 | 3F 新风机组负荷偏高 |
| 中优 | 3 | 2F 照明、B1 水泵、5F 空调 |
| 低优 | 1 | 屋顶冷却塔振动告警 |

每条告警必须包含：

- 设备编码和事件标题
- 位置
- 当前值
- 基线偏差
- 发生时间
- 优先级标签
- 状态标签
- 查看详情入口

### 4.3 工单列表

工单列表固定展示 2 条待处理工单：

| 工单号 | 标题 | 进度 | 状态 | 责任人 | 截止 |
|---|---|---:|---|---|---|
| WO-BUILDING-031 | 处置 3F 新风机组负荷偏高 | 65% | 处理中 | 暖通运维一组 | 今天 16:30 |
| WO-BUILDING-032 | 复核 2F 公区照明回路夜间未闭锁 | 30% | 待复核 | 电气运维二组 | 明天 10:00 |

### 4.4 底部状态栏

底部状态栏展示今日累计口径，与顶部“活跃告警”不是同一口径：

- 上次同步：实时递增后归零
- 在线运维人员：6 到 9 人小幅浮动
- 今日已处理工单：8 件
- 今日新增告警：237 条

“今日新增告警 237 条”为累计口径，Tooltip 中需说明它与“5 条活跃告警”的区别。

## 5. 核心组件

### 5.1 `SmartOperationsWorkspace`

页面根组件，负责：

- 组合数据快照
- 管理筛选范围
- 更新时间和同步状态
- 生成 `liveAlerts` 与 `liveTasks`
- 组织左右两栏布局

### 5.2 `OperationsKpiCard`

顶部指标卡组件。

当前设计要求：

- 不展示无业务含义的 mini trend 波浪线
- 标题字号大于普通标签
- 数值使用数字字体
- 副文案直接说明业务口径
- 卡片支持 Tooltip

### 5.3 `FocusSummary`

优先事项组件，用于告诉值班人员“当前最先处理什么”。

内容要求：

- 文案必须足够具体
- 至少包含设备、当前值、基线偏差、工单号、责任班组和处置动作
- 设备名可点击，高亮对应告警

当前摘要：

```text
优先处理:BLDG-APT-3F 新风机组负荷偏高。当前负荷 112.4 kWh,较 30 天同时间段基线高 29.8%,已派发工单 WO-BUILDING-031。处置重点是过滤器压差、阀门开度和送回风温差,责任人为暖通运维一组;今天 16:30 前完成现场复核,若负荷 30 分钟内未回落,同步调整新风策略并升级为值班长复核。
```

### 5.4 `AlertCenter` 与 `AlertCard`

告警中心和告警卡片。

交互：

- 鼠标悬停告警时，高亮关联工单
- 告警支持 Tooltip 查看字段明细
- 高优告警有轻微脉冲提示
- “查看详情”按钮作为后续详情页入口

### 5.5 `TaskList` 与 `TaskCard`

巡检与工单组件。

交互：

- 鼠标悬停工单时，高亮状态
- 工单卡显示工单号、标题、责任人、截止时间、状态和进度
- 进度条必须使用真实进度，不允许全部 100%

### 5.6 `StrategyList`

“待优化项”组件。

这里展示可执行的运维待办，不展示建设规划。

当前内容：

- 完成 3F 新风机组过滤器更换
- 复核 2F 公区照明感应阈值
- 校准 B1 水泵压差报警阈值

### 5.7 `AgentChat`

智能体问答组件。

功能：

- 默认展示 1 个用户问题和 1 段结构化 AI 回答
- 顶部展示 4 个推荐问题
- 点击推荐问题后自动发送用户消息
- 显示 5 秒思考态
- 之后按约 30 字/秒流式输出
- 回答完成后展示 2 个相关追问

推荐问题：

- 总结当前能耗情况
- 峰值出现在什么时段?
- 给我三条优化建议
- 列出当前高能耗设备

输入框 placeholder：

```text
例如:3F 新风机组为什么负荷偏高?
```

## 6. 智能体回答规范

所有预置回答保持同一结构：

```text
【问题理解】
说明用户问题意图。

【核心结论】
直接给判断，不绕弯。

【分析依据】
列出数据依据和知识依据。

【原因分析】
列出可能原因，并说明可能性。

【排查与优化建议】
给出现场排查步骤和短中期优化动作。
```

注意事项：

1. 首屏不能刷出多条重复气泡。
2. 默认回答不能拆成多个气泡。
3. 推荐问题和追问都必须走同一条交互链路。
4. 思考态需要同时有三个跳点和“正在分析能耗数据...”文案。
5. 打字动画不能被页面时钟刷新重置。

## 7. 视觉规范

整体风格：

- 深蓝科技风
- 切角卡片
- 半透明深色底
- 青色弱发光
- 重要状态使用玫红、金色、绿色

主色：

| 用途 | 色值 |
|---|---|
| 页面背景 | `#020817` |
| 主高亮 | `#00D4FF` |
| 浅青高亮 | `#7AF7FF` |
| 正常状态 | `#22D3A0` |
| 高优告警 | `#FF4D8D` |
| 中优告警 | `#FFB800` |

字号层级：

| 类型 | 建议字号 |
|---|---:|
| 页面标题 | 46px |
| 组件标题 | 22px |
| KPI 数值 | 46px |
| KPI 标签 | 18px |
| KPI 副文案 | 16px |
| 卡片标题 | 20px |
| 告警字段值 | 15px |
| 智能体正文 | 14px |

视觉注意：

- 不使用无意义波浪线装饰。
- 不使用开发占位字段。
- 不使用“构件”作为业务术语，统一使用“设备”。
- 不让发光描边压过正文信息。
- 卡片信息不足时优先补充业务内容，其次再放大字号。

## 8. Tooltip 规范

Tooltip 统一使用 `dashboard-tooltip.tsx` 提供的 `tooltipAttrs`。

示例：

```tsx
{...tooltipAttrs({
  title: '健康运行',
  rows: [
    { label: 'API 延迟', value: '86ms' },
    { label: '最近一次心跳', value: '19:58:50' },
  ],
})}
```

使用场景：

- 顶部健康运行状态
- KPI 卡片
- 告警卡片
- 工单卡片
- 底部今日新增告警口径说明

## 9. 响应式布局

布局规则：

- 默认单列布局。
- `1280px` 以上使用左右两栏。
- 左栏承载处置链路：优先事项、告警、工单、待优化项。
- 右栏承载辅助判断：当前运维焦点、智能体问答。
- 标题和按钮不使用 viewport 字号缩放，避免极端宽度下失真。

移动端要求：

- 卡片不相互嵌套。
- 长标题允许换行。
- 按钮文字不能溢出。
- 智能体追问按钮允许换行排列。

## 10. 文件维护说明

### 10.1 数据维护

数据快照集中在：

```text
apps/editor/features/operations/lib/operations-dashboard.ts
```

新增或修改告警时，同步检查：

1. 顶部活跃告警数量。
2. 告警中心条数。
3. 优先级分布。
4. 关联工单数量。
5. 底部状态栏口径说明。

### 10.2 页面结构维护

页面结构集中在：

```text
apps/editor/features/operations/components/smart-operations-workspace.tsx
```

维护要求：

- 新增模块优先复用 `OperationsPanel`。
- 新增徽章优先复用 `StatusBadge`。
- 新增数字指标优先复用 `AnimatedNumber`。
- 智能体回答优先加入 `ANSWER_BANK`，不要在点击事件中硬编码。

### 10.3 样式维护

样式集中在：

```text
apps/editor/app/globals.css
```

维护要求：

- 智慧运维相关样式使用 `operations-` 前缀。
- 不要删除全局 `.metric-mini-trend`，该类仍被数据分析页使用。
- 不要把 Next.js dev overlay 当成业务 UI。
- 调整字号时要用 Playwright 读取实际 computed style，确认没有被 Tailwind 类覆盖。

## 12. 已知限制

1. 当前数据是前端固定快照，后续接接口时要保留同一数据口径。
2. 告警详情按钮目前是入口样式，尚未接详情抽屉或详情页。
3. 智能体回答为预置回答，尚未接真实模型服务。
4. 类型检查目前会被仓库既有无关错误阻断，主要在能耗分析和建模编辑器模块。

## 13. 后续扩展建议

优先级从高到低：

1. 接入真实告警与工单接口。
2. “查看详情”接入告警详情抽屉。
3. 工单进度接入流转记录。
4. 智能体接入真实能耗分析服务。
5. 为筛选下拉接入设备类型过滤。
6. 增加工单催办和复核记录入口。
